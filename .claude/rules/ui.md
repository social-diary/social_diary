# Where UI code goes, and how it plugs in

`UI/` is a folder per area. A file holds one thing; a module is one table.
Find a thing by its area first:

| Folder | Holds | Table |
|---|---|---|
| `Style/` | the design system: tokens, art, sounds, drawing, the book and cover, widgets, a person's pieces. Knows nothing of the diary | `ns.Style` |
| `Kit/` | generic frames: chrome, the virtual list, keys, pools, the confirm popups | `ns.UI.Chrome`, `Pool`, `Keys`, `Dialog` |
| `Paper/` | paper you can lay and turn: the surface kit, the house light (shadows from heights, the sheen), loose sheets, strips (and the card contract), note and link sheets | `ns.UI.Surface`, `Light`, `PaperStrip`, `LooseSheet`, ... |
| `Ink/` | the pen (strokes, nibs), the trail, ink blots | `ns.UI.Pen`, `InkTrail`, `InkBlot` |
| `Map/` | map art, the overlay data (generated by `Dev/map_overlays.py`), the heat-map sheet | `ns.UI.MapArt`, `MapSheet` |
| `Words/` | text formatters and the timeline's words | `ns.UI.Format`, `TimelineText` |
| `Journal/` | the book, its page registry and the pages (People, profile, timeline, Recently nearby, front matter, frontispiece) | `ns.UI.Journal` |
| `Journey/` | Your Diary: the page's parts, the plate, its words (`Text/`) | `ns.UI.YourDiary`, `JourneyPlate`, `JourneyText` |
| `Settings/` | the settings page, its kit, `Sections/` one file per section | `ns.UI.Settings` |
| `Windows/` | what opens outside the book: entry, picker, `Reunion/` toast, `Intro/` parcel | `ns.UI.Entry`, `Toast`, `Parcel` |
| `Blizzard/` | hooks into Blizzard's frames: tooltip, Social tab, AddOns settings signpost, key bindings | — |

## Namespaces

- A new module is a table on `ns.UI` (or a function on `ns.Style` if it is
  design system). Loose `ns.UI.<Function>` names are only for entry points
  another layer calls (Core, Capture, bindings, Features, tests).
- `tests/ui_layout.lua` lists both: the allowed loose names (with the caller
  that needs each) and the modules. Adding to either is a conscious edit
  there; the test says which list a stray name belongs on.
- `UI/Style/` must not read the diary (`ns.db`, `ns.Diary`, `ns.Journey`,
  `ns.Setting(`, `ns.UI`, ...). Pass what it needs in as an argument.

## Extension points

Everything that is a list of things registers through `ns.Registry`
(`Core/Registry.lua`: `Add`, `Core`, `Remove`, `Get`, `Ordered`; core
entries rank before or after equal orders as data, not as an `if`). Never
add a hand-written list or an `if view == ...` chain for these:

| To add | Call | Spec documented at |
|---|---|---|
| a journal page or ribbon | `ns.UI.Journal.RegisterPage(key, spec)` | `UI/Journal/Pages.lua` |
| a settings section | `ns.UI.Settings.RegisterSection(key, spec)` | `UI/Settings/Page.lua` |
| a mark on the plates | `ns.UI.JourneyPlate.RegisterMark(kind, spec)` | `UI/Journey/Plate.lua` |
| a pass over the plates | `ns.UI.JourneyPlate.RegisterPass(key, spec)` | `UI/Journey/Plate.lua` |
| a margin note | `ns.UI.JourneyMargin.Register(kind, spec)` | `UI/Journey/Margin.lua` |
| caption words | `ns.UI.JourneyText.RegisterCaption(key, spec)` | `UI/Journey/Text/Caption.lua` |
| entry prose | `ns.UI.JourneyText.RegisterLines(key, spec)` | `UI/Journey/Text/Prose.lua` |
| art | `ns.Style.AddArt(key, paths, tint)` | `UI/Style/Art.lua` |

A page's ribbon also needs its hand-placed pieces: a cut-out in the front
matter's contents (`UI/Journal/Front.lua`, or `contents = false`) and a
ribbon on the parcel's closed book (`UI/Windows/Intro/`). A test fails
until both exist.

## Cards on a paper strip

A margin card is `ns.UI.PaperStrip(parent, hooks)` with `plan`, `draw`,
`again`, `smaller`, `nearest`; the contract and what a card may touch are in
the header above `ns.UI.PaperStrip` (`UI/Paper/Strip.lua`). Never override
a strip's `Layout`, `Smaller` or `Nearest`, read `PAPER_STRIP`, or touch its
private fields: `tests/kinds.lua` fails on each. Tooltip lists go through
`Style.TipList`.

## Load order

- The TOC is load order, and load order is event-handler order and the order
  frames and fonts are made. Splitting a file keeps the pieces at its TOC
  line, in its order.
- A file may read another at load (`local X = ns.UI.Y`) only if that file
  loads earlier; otherwise look it up when called.
- Shared mutable state lives on the module table and is read when called,
  never captured at load.

## Proving a refactor changed nothing

`tests/golden/golden.sh <label>` dumps everything the UI draws and stores;
`tests/golden/compare.sh <before> <after>` must print nothing (suite.txt's
check counts aside). Take the `before` label first. See the scripts'
headers.
